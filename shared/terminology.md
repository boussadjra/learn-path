# Terminology

Use one plain term for each core concept so skills remain consistent and vendor-neutral.

| Term | Meaning |
| --- | --- |
| **learner** | The person developing understanding through real work. Use **user** when discussing product or tool interaction rather than learning behavior. |
| **agent** | The AI-enabled system applying a skill and helping with the work. |
| **skill** | A reusable set of behavioral instructions for an agent. |
| **path** | An adaptive route from the current goal through relevant concepts, actions, evidence, and next decisions. It is not a fixed curriculum. |
| **plan** | A sequence of work to complete. Unlike a path, it does not necessarily state what understanding should emerge. |
| **concept** | A specific unit of understanding whose state can be inferred from evidence. |
| **mental model** | A causal representation that helps the learner explain and predict system behavior. |
| **evidence** | An observation that supports, weakens, or changes a claim or hypothesis. |
| **hypothesis** | A testable explanation for an observation. |
| **trade-off** | A choice in which options optimize for different outcomes or costs. |
| **constraint** | A condition the solution must respect. |
| **symptom** | The observed failure or unwanted behavior. |
| **cause** | The condition directly producing the symptom. |
| **root cause** | The deeper condition that allowed or repeatedly produces the cause. |

## Usage guidance

Prefer **learner**, **user**, or the person's role when it is known. Do not repeatedly call someone a student, beginner, junior developer, or expert. Understanding is concept-specific rather than a global rank.

Use **path** carefully. A path emerges from real work:

```text
current goal
    ↓
relevant concept
    ↓
useful action
    ↓
evidence
    ↓
next decision
```

Do not use **path** as a decorative synonym for a checklist, tutorial, course, or fixed lesson sequence.
