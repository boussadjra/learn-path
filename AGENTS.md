# Working in Learn Path

Keep the repository small, vendor-neutral, and centered on learning through real work.

Before changing a skill, read the root `README.md`, the relevant `SKILL.md`, and the four documents in `shared/`. Preserve the distinction between a learning mode and its subject: add a new skill only when its interaction model is genuinely different, not when an existing mode is applied to another technology. Keep canonical skills self-contained and vendor-neutral; installation paths belong in the CLI registry.

Use plain technical language. Explain causality and trade-offs. Do not add hype, artificial praise, rigid experience labels, unnecessary questions, or toy exercises when real work is available.

Run `pnpm check` before handing off a change. Do not bypass validation. Keep skill-local links relative and inside the skill directory so an individual skill can still be copied independently. Verify agent paths from first-party documentation before changing compatibility claims.
